# Codex 额度桌宠设计

日期：2026-10-22

## 目标与范围

为 Windows 上的 Codex Desktop 制作一个常驻桌面的 2D 桌宠。宠物图片下方持续显示当前 ChatGPT 账号的 Codex 使用额度。当观察到剩余额度下降时，在对应数值旁播放一次 `-X%` 飘字动画。宠物根据本机 Codex Desktop 是否正在生成或执行任务，以及额度是否偏低，在用户提供的三张图片之间切换。

“工作中”状态只监控这台电脑上的 Codex Desktop，不监控 CLI、IDE 插件或云端任务。额度则是 ChatGPT 账号共享的 Codex 使用额度，其他设备或入口的使用也可能使它下降；它不是 OpenAI API 的用量或余额。

## 用户图片

三张图片都是带透明背景的 PNG。实现时复制到项目资源目录，保持原图内容和透明度：

| 状态 | 原始文件 | 尺寸 |
| --- | --- | --- |
| 工作中 A | `C:\Users\yuzhi\Downloads\专注打字的银发AI萌宠.png` | 1536 × 1024 |
| 无工作 B | `C:\Users\yuzhi\Downloads\ChatGPT 图像 2026年10月22日 10_36_06-2.png` | 1448 × 1086 |
| 快没额度 C | `C:\Users\yuzhi\Downloads\ChatGPT 图像 2026年10月22日 10_36_03-1.png` | 1448 × 1086 |

图片在同一视觉高度内缩放、底部对齐，切换时桌宠底线不跳动。窗口背景透明，图片透明区域不显示矩形底色。

## 技术方案

使用 Electron 构建 Windows 桌面应用。主进程负责 Codex 数据连接、任务记录观察、状态归一化、窗口与托盘；渲染进程负责图片、额度卡片和动画。渲染进程只通过受限 preload API 接收所需状态与触发“刷新额度”等明确操作，不直接访问文件系统、凭据或 Node API。

### 额度来源

主进程启动本机 `codex app-server` 的 stdio JSON-RPC 连接，完成 `initialize` 握手后读取 `account/read` 和 `account/rateLimits/read`，并处理 `account/rateLimits/updated` 通知。按固定间隔重新读取额度，补足另一进程内发生的额度变化；初始间隔为 60 秒。连接失败时自动重连，避免并发重复启动。使用 Codex 已有的 ChatGPT 登录状态，不读取或解析 `auth.json`，不在日志中记录令牌。

将响应中的 `rateLimitsByLimitId` 作为额度桶来源；若没有该字段，则使用 `rateLimits`。对每个额度桶保留实际返回的 `primary`、`secondary` 窗口，按 `windowDurationMins` 标注周期，并显示 `100 - usedPercent` 的剩余百分比与 `resetsAt` 对应的本地重置时间。空窗口不虚构为 5 小时或 7 天额度，也不把不同模型或额度桶合并成一个错误的总百分比。相同额度桶和周期的重复数据只显示一次。

首次读取只建立动画基准。后续同一额度桶、同一周期且重置时间不变时，若剩余百分比下降，按两次已观察到的数值差播放一次 `-X%` 动画。若多个实际消耗发生在两次读取之间，合并为一次飘字；数据源不能保证逐次任务计费事件。重置、重新连接或新额度桶出现时只更新基准，不播放扣除动画。数据显示和动画数值采用同一精度，避免显示为 `-0%`。

### 工作状态来源

只读观察本机 Codex 的任务索引数据库。`thread_history_1.sqlite` 的 `thread_turns` 提供实时任务状态；只将 `status = 'inProgress'` 且 `completed_at` 为空的近期任务纳入判断，再通过 `state_5.sqlite` 的 `threads.originator = 'Codex Desktop'` 筛选桌面应用会话。不查询任务文本，也不上传会话内容。任一桌面任务处于进行中时判为“工作中”；任务结束时回到“无工作”。Codex Desktop 退出或数据库不可读时回到“无工作”。

这个记录格式是本机当前版本的内部实现，而非对第三方应用承诺稳定的公开状态接口。文件观察与解析集中在一个模块；解析异常不影响额度显示，并在界面中提供可诊断但不包含会话内容的状态。

### 状态优先级

1. 任一实际返回、正在显示的额度窗口剩余 `≤20%`：显示 C。
2. 否则，Codex Desktop 正在生成或执行任务：显示 A。
3. 其他情况：显示 B。

额度不可用时不等同于 0%，不能因此触发 C。低额度状态解除后，按当时的工作状态回到 A 或 B。

## 窗口与交互

透明、无边框、始终置顶的窗口默认位于主屏幕右下角。用户可以拖动宠物图片，应用记住窗口位置，并在屏幕分辨率或显示器布局变化时把窗口移回可见区域。图片下方的紧凑额度条对每个可用窗口只显示剩余百分比和细进度条；悬停时显示周期标签与重置时间。每次观测到额度下降，`-X%` 从对应数值旁向上移动并淡出。图片和额度条按所选大小一起缩放。

右键宠物图片的菜单与托盘菜单提供“刷新额度”“开机启动”“桌宠大小”（75%／100%／125%／150%）和“退出”；大小选择持久保存。托盘图标可显示或隐藏桌宠。开机启动默认关闭，用户可从菜单开启。窗口关闭操作隐藏到托盘；明确选择“退出”才结束后台进程。

## 失败与恢复

- 登录缺失或额度读取失败：额度条显示“额度暂不可用”，悬停可见上次成功更新时间；后台重试，不把未知值显示成 0%。恢复时建立新基准，不补播扣除动画。
- Codex App Server 意外退出：清理子进程资源，限速重连；桌宠和任务状态观察继续运行。
- 任务索引缺失、损坏或格式变化：工作状态退回无工作；额度读取和卡片不受影响。只记录不含任务内容的错误信息。
- 应用退出：关闭文件观察器、JSON-RPC 连接和子进程，防止残留后台进程。

## 验收标准

1. 三张原图在透明窗口内正确显示，底部对齐；窗口可拖动、置顶、隐藏到托盘并退出。
2. 已登录的 Codex 账号返回额度时，每个实际返回的额度窗口在图片下方显示进度条与剩余百分比，悬停可见周期与重置时间；缺失窗口不显示虚构数据。
3. 本机 Codex Desktop 开始任务时显示 A，完成后显示 B；剩余 `≤20%` 时显示 C，并优先于 A。
4. 同一额度窗口从较高剩余值下降到较低值时，只播放一次正确差值的 `-X%` 动画；首次加载、重置和断线恢复不播放扣除动画。
5. 额度读取失败时显示不可用和上次成功更新时间，不误显 0%；任务记录解析失败不会使窗口崩溃。
6. 通过单元测试覆盖额度响应归一化、差值计算、重置判断、状态优先级和任务状态检测；通过本机 Codex Desktop 实际运行验证开始与完成切换，并检查窗口视觉效果。

## 依据与边界

- OpenAI 官方 Codex App Server 文档列出 `account/rateLimits/read`、`account/rateLimits/updated`、额度窗口字段以及 JSON-RPC stdio 协议：https://learn.chatgpt.com/docs/app-server
- 当前机器的 Codex Desktop SQLite 索引经只读检查，当前对话的 `threads.originator` 为 `Codex Desktop`，其最新 `thread_turns.status` 在执行期间为 `inProgress`。会话 JSONL 在该任务进行时未实时更新，因此不能用于即时切换。这些内部表名和字段可能随 Codex 版本变化，属于任务状态检测的主要维护风险。
- 60 秒轮询意味着动画反映两次采样之间观察到的额度差，无法保证每次底层消耗都有一条独立动画。
